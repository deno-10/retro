# Retro

Доска для ретроспектив спринта. Один бинарник на Go без внешних зависимостей, фронт — обычный JS без сборки.

## Что умеет (итерация 1)

- Доска по ссылке, четыре шаблона колонок (Классика, Start/Stop/Continue, 4L, Mad/Sad/Glad).
- Карточки с подписью или анонимно. В фазе записи чужие карточки скрыты — на сервере, а не в браузере.
- Фазы: запись → показ → голосование → обсуждение. Переключает ведущий (создатель доски).
- Голосование точками, лимит на участника задаёт ведущий.
- Изменения видны всем сразу (SSE), счётчик участников онлайн.
- Экспорт доски в Markdown.
- Хранение: JSON-файл `data/boards.json`.

## Запуск

Нужен Go 1.22+.

```
go run .                                   # http://localhost:8080
go test ./...
go build -o retro . && ./retro -addr :8080 -data /var/lib/retro/boards.json
```

Docker:

```
docker build -t retro .
docker run -d -p 8080:8080 -v retro-data:/app/data --name retro retro
```

## Структура

```
main.go              точка входа, флаги, embed web/
internal/model       предметная область: доска, фазы, голоса, права — без HTTP и БД
internal/store       интерфейс Store и JSON-реализация
internal/hub         подписки SSE по доскам
internal/server      HTTP: REST, SSE, статика
web/                 index.html, app.js, style.css
```

## API

Все запросы, кроме экспорта, несут заголовок `X-Participant` (для SSE — параметр `?participant=`): 8–64 символа `[A-Za-z0-9-]`, браузер генерирует его сам.

| Метод | Путь | Тело | Что делает |
|---|---|---|---|
| GET | `/api/templates` | — | список шаблонов |
| POST | `/api/boards` | `{title, template}` | создать доску; автор — ведущий |
| GET | `/api/boards/{id}` | — | доска глазами участника |
| GET | `/api/boards/{id}/events` | — | SSE: событие `board` с представлением доски на каждое изменение |
| GET | `/api/boards/{id}/export.md` | — | Markdown (после фазы записи) |
| POST | `/api/boards/{id}/phase` | `{phase}` | сменить фазу (ведущий) |
| POST | `/api/boards/{id}/vote-limit` | `{voteLimit}` | лимит голосов (ведущий) |
| POST | `/api/boards/{id}/cards` | `{columnId, text, author}` | добавить карточку (запись, показ) |
| PATCH | `/api/boards/{id}/cards/{cardId}` | `{text}` | изменить свою карточку; ведущий — любую |
| DELETE | `/api/boards/{id}/cards/{cardId}` | — | удалить свою карточку; ведущий — любую |
| POST | `/api/boards/{id}/cards/{cardId}/vote` | — | поставить/снять голос (голосование) |

Ошибки: `{"error": "..."}` с кодами 400 (данные), 403 (права), 404, 409 (фаза или лимит голосов).

## Как устроен realtime

Клиент держит одно SSE-соединение. Любая мутация идёт через `store.Update` — атомарно, под мьютексом, с откатом при ошибке, — затем `hub.Notify(boardID)`. Каждое SSE-соединение по сигналу перечитывает доску и отправляет участнику его представление `Board.View`. Доски маленькие, поэтому отправляется вся доска целиком, а не дифф: нет состояния на клиенте, нечему разъезжаться. Переподключение делает сам `EventSource`; сервер шлёт комментарий-пинг раз в 25 с, чтобы прокси не рвали соединение.

## Идентификация

Браузер один раз генерирует id участника и хранит в `localStorage`. Это не аутентификация: кто знает ссылку, тот и участник. Ведущий — создатель доски в том же браузере. SSO — следующая итерация.

## Дальше

1. SQLite (`modernc.org/sqlite`, без CGO): таблица `boards(id, data, created_at, updated_at)`, доска — JSON-документ. Это новая реализация интерфейса `Store`, остальной код не меняется. Postgres (`jsonb`) — тем же путём.
2. SSO по OIDC (Okta / Azure AD / Keycloak): участник = `sub` из токена, роль ведущего переживает смену браузера.
3. Группировка карточек drag-and-drop.
4. Action items с ответственным и переносом в следующее ретро; история досок команды.
5. Таймер фазы.

## Ограничения

- Один инстанс: подписки живут в памяти процесса. Для нескольких реплик нужен Redis pub/sub или липкие сессии на балансировщике.
- JSON-файл переписывается целиком при каждом изменении — для десятков досок это незаметно, для тысяч нужен SQLite.
- Тексты карточек никак не модерируются; максимум 2000 символов.
