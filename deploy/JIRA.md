# Создание задач Jira из решений ретро

На этапе «Обсуждение» ведущий отмечает незакрытые решения флажком «В Jira» и
нажимает «Создать в Jira». Для каждого выбранного решения создаётся отдельная
задача, а ссылка появляется у решения и сохраняется в базе. Остальные карточки
и решения в Jira не передаются. Проект и тип задачи задаёт администратор сервиса.

Заголовок задачи — текст решения (до 240 символов), описание содержит полный
текст, название ретро и имя ответственного. Свободный текст ответственного
не превращается в Jira assignee: исполнитель определяется настройками проекта.
Автор задачи (reporter) определяется по токену через `/rest/api/2/myself`.
Изменения текста, исполнителя и статуса в Retro и Jira после создания **не
синхронизируются**. При переносе незакрытого решения в следующее ретро ссылка
сохраняется; повторная задача не создаётся.

## Подключение

Нужны адрес Jira, ключ проекта, числовой ID типа обычной задачи и учётная запись
с правами Browse Projects и Create Issues. Поля summary, description, labels
должны быть доступны при создании. ID типа и дополнительные обязательные поля
можно получить у администратора Jira или из create metadata API проекта.
Подзадачи, OAuth и scoped Cloud tokens через api.atlassian.com в этой версии
не поддерживаются.

- Jira Data Center: `JIRA_DEPLOYMENT=datacenter`, `JIRA_AUTH_MODE=bearer`,
  персональный токен (PAT) или разрешённый администратором токен интеграции.
- Jira Cloud: `JIRA_DEPLOYMENT=cloud`, `JIRA_AUTH_MODE=basic`, `JIRA_USER` —
  почта аккаунта, токен — API token без scopes для адреса `https://…atlassian.net`.

Для постоянного сервиса предпочтительна отдельная учётная запись интеграции
с доступом только к нужному проекту. Токен не попадает в браузер, API Retro,
логи или образ контейнера. Не присылайте его в чат и не добавляйте в Git.

### Docker Compose

1. Заполните параметры `JIRA_*` в локальном `.env` по `.env.example`.
2. Создайте `deploy/secrets/jira_token` редактором и поместите туда только токен.
   Каталог уже исключён из Git и Docker build context.
   На Linux файл должен читаться UID 10001 (пользователь Retro в контейнере):
   `sudo chown 10001:10001 deploy/secrets/jira_token` и
   `sudo chmod 400 deploy/secrets/jira_token`. Compose монтирует файл с правами
   исходного файла. Для запуска без Docker оставьте владельцем своего
   пользователя и используйте `chmod 600`.
3. При обязательных полях проекта задайте `JIRA_EXTRA_FIELDS` как JSON-объект,
   например `'{"customfield_12345":{"value":"Команда"}}'`. Он добавляется к
   `fields` запроса. Переопределять project, issuetype, summary, description,
   labels, assignee нельзя. Секреты в дополнительные поля не помещайте.
4. Соберите и запустите с дополнительным файлом:

   ```sh
   docker compose -f compose.yaml -f compose.jira.yaml up -d --build
   ```

Дополнительный файл разрешает контейнеру исходящий доступ к Jira, не публикуя
порт 8080. Внутренняя корпоративная Jira также требует доступной серверу сети
или VPN и доверенного TLS-сертификата. Проверка сертификата не отключается.
При последующих обновлениях/перезапусках используйте оба файла Compose.

### Локальный запуск

Приложение читает переменные окружения; файл `.env` автоматически не загружается.
Пример (значения проекта и типа нужно заменить своими):

```sh
export JIRA_BASE_URL=https://jira.example.org
export JIRA_DEPLOYMENT=datacenter
export JIRA_PROJECT_KEY=TEAM
export JIRA_ISSUE_TYPE_ID=10001
export JIRA_AUTH_MODE=bearer
export JIRA_TOKEN_FILE="$PWD/deploy/secrets/jira_token"
# Необязательно: ссылка на ретро будет добавлена в описание задачи.
export RETRO_PUBLIC_URL=https://retro.example.org
go run . -addr 127.0.0.1:8080
```

Можно передать `JIRA_TOKEN` вместо `JIRA_TOKEN_FILE`, но не оба одновременно.
Без настроек Jira Retro продолжает работать, а интерфейс объясняет, что Jira
не подключена. Частично заполненные или некорректные настройки останавливают
запуск с сообщением без секрета. Уже сохранённые ссылки видны и без подключения.

## Сбои и повторная отправка

Перед запросом в Jira сервер атомарно резервирует отправку в базе. Одновременные
нажатия, повтор HTTP-запроса и перезапуск Retro не запускают её заново. Сеть не
блокирует транзакцию базы; одновременно выполняется не более четырёх запросов.

Явный отказ Jira (например, 400 или 403) показывается у решения. После исправления
настроек его можно выбрать и отправить снова. При таймауте, 5xx, неожиданном
ответе или аварийном завершении результат считается неопределённым: автоматической
повторной отправки нет. Нажмите «Проверить в Jira» — поиск по уникальной метке
восстановит ссылку без создания новой задачи. Индекс Jira может обновляться не сразу;
пустой поиск не снимает блокировку. Поиск доступен и по ссылке «Открыть поиск в Jira».

Пока результат неизвестен, нельзя изменять/удалять это решение или создавать
следующее ретро: иначе можно потерять связь с уже созданной задачей. Если запрос
вообще не дошёл до Jira и задача так и не появилась, администратор проверяет
проект вручную и при необходимости создаёт её в Jira с меткой из поисковой ссылки,
затем нажимает «Проверить в Jira». Кнопки безусловного повтора намеренно нет.
Не удаляйте метку до завершения восстановления. Если настройки проекта/адреса
изменились, для проверки старой отправки восстановите прежнее подключение.

Общий пароль команды не даёт индивидуальной аутентификации. Ведущий определяется
существующей моделью participant ID; доступ к Retro означает доступ к сервисной
учётной записи Jira через разрешённые действия ведущего. Не публикуйте сервис без
предусмотренной общей авторизации.

## Проверка

Регрессии используют временные базы и локальную имитацию Jira. Команды:
`go test ./...`, `go vet ./...`, `npm test`, `npm run test:integration`.
Настоящие задачи эти тесты не создают. Проверка конкретной корпоративной Jira
проводится отдельно после подключения, с заранее выбранным тестовым решением.

API основан на [создании задач REST v2](https://developer.atlassian.com/cloud/jira/platform/rest/v2/api-group-issues/),
[примерах Data Center](https://developer.atlassian.com/server/jira/platform/jira-rest-api-examples/),
[поиске Cloud](https://developer.atlassian.com/cloud/jira/platform/rest/v3/api-group-issue-search/),
[PAT Data Center](https://confluence.atlassian.com/enterprise/using-personal-access-tokens-1026032365.html)
и [Basic auth Cloud](https://developer.atlassian.com/cloud/jira/platform/basic-auth-for-rest-apis/).
